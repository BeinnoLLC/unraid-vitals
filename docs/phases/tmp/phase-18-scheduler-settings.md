## P18-01 — Schedule registry

**Type:** enhancement · **Priority:** high

One source of truth for every scheduled job.

- Each job declared once: id, label, command, default schedule, lock name, timeout
- User values stored in `vitals.cfg` as `SCHED_<JOB>` and `SCHED_<JOB>_ENABLED`
- `install.sh --reapply` writes every `/etc/cron.d/unraid-vitals-*` file from the registry and removes files for jobs that no longer exist
- `remove.sh` removes by glob, so a new job can never be left behind on uninstall

Acceptance: adding a job to the registry and re-applying creates its cron file with no other code change.

## P18-02 — Schedules panel on the settings page

**Type:** enhancement · **Priority:** high

- One row per job: enabled switch, frequency, last run, next run
- Frequency presets: every N minutes, hourly at minute M, daily at HH:MM, weekly on a day
- Advanced mode accepts a cron expression
- Validation on the server: five fields, characters limited to digits and `* , - /`, ranges checked. The value is written into a root cron file, so anything else is rejected
- Shows the next three run times before saving

Acceptance: a value containing a newline or shell characters is rejected with HTTP 400 and the cron file is unchanged.

## P18-03 — AI agent schedules, per agent

**Type:** enhancement · **Priority:** high

All five agents run hourly together. Disk health does not change hourly; thermal can.

- Enable switch and schedule per agent (`disks`, `thermal`, `pools`, `network`, `general`)
- `analyze.mjs` already accepts agent ids as arguments, so each cron line passes its own
- All agent jobs share one lock, so they still run one at a time

Acceptance: `disks` set to daily and `thermal` to every 30 minutes produce runs at those times in the `runs` table.

## P18-04 — Retention and prune schedule

**Type:** enhancement · **Priority:** low

- Prune time adjustable
- Retention for KB documents and research jobs, not only flash rollups
- `prune.php` is generated by a heredoc in `install.sh`; move it to `scripts/` as a normal file

Acceptance: research jobs older than the retention setting are removed by the prune job.

## P18-05 — Run now, and job status

**Type:** enhancement · **Priority:** medium

- "Run now" button per job, CSRF-protected, refuses if the job's lock is held
- Per job: last start, duration, exit status, last lines of output
- One `job_runs` table for all jobs, extending the agents' `runs` table

Acceptance: "Run now" on the agents job while it is running returns "already running" and starts nothing.

---

## P18-06 — Quiet hours and busy-system guard

**Type:** enhancement · **Priority:** medium

- Quiet hours window in which heavy jobs do not start
- Heavy jobs skip when a parity check or mover is running
- Jobs are marked light or heavy in the registry
- A skipped run is recorded with its reason

Acceptance: the storage scan does not start during a parity check and the skip appears in job status.

---

## P18-07 — Time windows are correct at any sample interval

**Type:** bug · **Priority:** high

The ring and the UI assume one sample per minute.

- `VITALS_RING_MAX` is 1440 points: 24 hours at 1 minute, 10 days at 10 minutes
- The range selector slices by point count (`ring.slice(-range)`), so "Last hour" at a 5-minute interval shows 5 hours
- Slice by timestamp; size the ring by time

Acceptance: at a 5-minute interval, "Last hour" shows 12 points spanning 60 minutes.

---

## P18-08 — Locks and timeouts for every job

**Type:** enhancement · **Priority:** medium

Only the agents job uses `flock`. The collector has no overlap guard, and a slow `docker stats` or SMART read can stack runs.

- Every job runs under its registry lock and timeout
- A run killed by timeout is recorded as such

Acceptance: a collector run forced to hang is killed at its timeout and the next run starts normally.

---

## P18-09 — UI refresh interval

**Type:** enhancement · **Priority:** low

- Polling interval adjustable (5 s to 60 s, and paused)
- Polling pauses when the browser tab is hidden

Acceptance: no requests are sent while the tab is in the background.
